# Generate Weekly Menu

Generate one or more weekly menus and publish them (validate → sync manifest → commit → push).

## STRICT CONSTRAINTS — follow exactly, no exceptions

- Do NOT read any existing week JSON files for reference or style calibration.
- Do NOT output the JSON to the chat. Write it directly to the file using the Write tool.
- Do NOT explain your reasoning, narrate steps, or print intermediate plans to the chat.
- Do NOT re-read prompt files more than once per generation run.
- Read each prompt file exactly once, in one tool call each, then generate immediately.

## Step 1 — Resolve target week(s)

Today's date is in the `currentDate` system context. Use ISO 8601 week numbering (weeks start Monday, Europe/Vilnius timezone).

Resolve plain-English input to one or more week IDs:
- "this week" → current ISO week
- "next week" → current + 1
- "next two weeks" → current + 1 and current + 2
- "2026-W25" → that exact week
- "weeks 24 and 25" → both

For each resolved week ID:
1. Check if `data/weeks/{weekId}.json` already exists. If it does, ask the user before overwriting.
2. Derive `start_date` (Monday) and `end_date` (Sunday) from the week ID.

## Step 2 — Read prompt files (once, in parallel)

Read these three files in a single parallel batch — do not read them separately or repeatedly:
- `prompts/weekly-menu-generation-prompt.md`
- `prompts/Family-context.md`
- `prompts/json-schema.md`

## Step 3 — Generate and write (four passes)

The output JSON is large. Write it in four passes to stay within output limits.

**Pass 1** — Skeleton (Write tool, ~6 KB):
Write the file with sentinel placeholders in `recipes`:

```json
{
  "schema_version": "2.0",
  "language": "ru",
  "week": { ... },
  "fixed_school_snack": { ... },
  "menu": [ ...7 days with titles + recipe_ids... ],
  "recipes": ["__FIRST_HALF__", "__SECOND_HALF__"],
  "shopping_list": [],
  "daily_nutrition": []
}
```

**Pass 2** — Recipes first half (Edit tool, ~35 KB):
Replace `"__FIRST_HALF__"` with the first half of recipe objects by array index
(roughly recipes 1–N/2). Full objects: id, title, ingredients[], instructions[],
nutrition_estimate_per_person, serves, etc.

**Pass 3** — Recipes second half (Edit tool, ~35 KB):
Replace `"__SECOND_HALF__"` with the remaining recipe objects (index N/2+1 onward).
After this pass `recipes[]` is a valid JSON array with no sentinel strings.

## Step 4 — Generate shopping metadata

```bash
node scripts/generate-shopping-list.js data/weeks/{weekId}.json --template
```

This writes `data/weeks/{weekId}-shopping-meta.json` with all ingredient keys
pre-filled. `display_name` is auto-populated as a capitalised `recipe_key` — only
correct it if the capitalised key looks wrong. `category` and `note` are null.

**Pass 4** — Fill metadata (Write tool, ~3–4 KB):
Read `data/weeks/{weekId}-shopping-meta.json` (just generated by the script above).
For every entry fill in the two null fields, and adjust `display_name` only where needed:
- `display_name`: prettified Russian label — auto-filled from recipe_key; adjust if needed
- `category`: Russian category heading (e.g. "Рыба и морепродукты")
- `note`: short Russian purchase note, or keep null if not needed

**Shopping note rules:**
- Notes must NOT contain any banned fruit terms: вишня/вишни, яблоко/яблоки, груша/груши, абрикос/абрикосы, персик/персики (or their English equivalents).
- Do not write notes like "без вишни" — that embeds a banned term. Instead say "проверить состав" or omit the note.

## Step 5 — Assemble shopping list

```bash
node scripts/generate-shopping-list.js data/weeks/{weekId}.json data/weeks/{weekId}-shopping-meta.json
```

Aggregates ingredient quantities from recipes[], joins with metadata on (recipe_key, unit),
writes `shopping_list[]` into the week JSON. Exits non-zero if any ingredient has no
metadata entry — fix the metadata file and re-run if that happens.

## Step 6 — Validate and fix

```bash
node scripts/validate-week.js data/weeks/{weekId}.json
```

If validation fails:
- Show `[FAIL]` lines to the user
- Fix with targeted Edit calls only — do not regenerate the whole file
- Re-run until it passes or you cannot fix without user input

## Step 7 — Publish

Once validation passes:

```bash
node scripts/sync-weeks-index.js
git add data/weeks/{weekId}.json data/weeks/index.json
git commit -m "W{nn}: generate menu for {weekId}"
git push
```

## Multiple weeks

Process sequentially — finish validate + commit for week N before starting week N+1.

## Done

One-line summary per week: week ID, validation result, push status.
